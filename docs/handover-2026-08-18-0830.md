## 2. What was done this session

### Why the site was stale
Three independent causes, all now fixed:
1. `uat-staging` was pinned at Alpha 0.6 — eight commits behind `main`.
2. The deployed image predated even that; the container had only been restarted.
3. Port 443 belonged to the unrelated `phitopolis-revamp` site, so visitors
   were looking at a different product entirely.

### Why sections rendered blank (the real bug)
Two separate defects with an identical symptom — heading visible, body missing:

**a. `Reveal` deadlocked itself.** Hidden state is `clip-path: inset(100%)`.
Chromium folds clip-path into the intersection computation, so a clipped
element reports `intersectionRatio` **exactly 0** while inside the viewport
(proven with a synthetic control: unclipped 300x300 div = ratio 1, same div
clipped = ratio 0). `useInView` asked for `amount: 0.05`, so once an element
painted its own hidden state it could never satisfy the threshold again.
Latent since Alpha 0.6 (`amount` was 0.3), which is why it looked like a race:
if the observer's first callback beat motion's first paint it revealed,
otherwise that section stayed blank for the life of the page.
Fix: `amount: "some"` (threshold 0).

**b. `SectionBeat` pre-hid content it could never restore.**
`Timeline.fromTo()` forces `immediateRender: true`, so GSAP wrote the from-vars
when the tween was *built*, not when it played — inverting the file's own
load-bearing INVARIANT (`SectionBeat.tsx:63`) that content "simply renders lit"
if the trigger never fires. Combined with `once: true` + `invalidateOnRefresh`,
any routine refresh (resize, late image, fonts) re-hid a section permanently.
Fix: `immediateRender: false`, dropped `invalidateOnRefresh` from the entrance
trigger, entrance armed at `BEAT_ENTER_START` ("top bottom"), plus an `onEnter`
that jumps to lit if the section is already on screen, plus a 2s failsafe.

## 3. Known gaps

### 3.1 Preloader does not actually pre-load (highest value)
Confirmed in code. `AppShell.tsx` warms only:
- `HERO_CRITICAL_ASSETS` — **one** file, `/phitopolis_logo_hero.svg`
- `BACKGROUND_ASSET_CAP` — 15 assets, taken from an **unordered filesystem
  glob**, so which 15 is arbitrary
- 4 route chunks via `router.preloadRoute` (`/about`, `/services`, `/blog`,
  `/contact`)

Deliberately excluded, with reasoning in the comments: the hero's 25-photo
drift wall, all monolith/R3F textures, the hero video, and every below-fold
section image. So when the reader scrolls into a section, its imagery and
canvases start from nothing — exactly the symptom described.

To get Lusion-style behaviour (preloader readies assets; scroll only consumes
what is already prepared) the model has to change from "warm a token handful
then release" to:
1. an explicit manifest of what each section needs (not a glob slice),
2. decode-complete gating (`img.decode()`, not just `onload`), and texture
   upload for R3F rather than fetch alone,
3. a progress bar driven by that manifest, and
4. section components that *consume* a ready cache instead of initialising.

Non-trivial: it touches `AppShell`, `Preloader`, the hero, and every
image-bearing section. Worth scoping as its own piece of work.

### 3.2 Transitions still jagged
- `services` reliably snaps: lit -> ~0.27 opacity at `y≈83` -> re-animates.
  Positive `y` means it is the entrance from-state, not the intended exit
  recede (which uses `y: -40`). The `onEnter` guard does not catch it —
  suspected cause is `CapabilityRack` nesting its own `SectionBeat` inside
  `#capabilities`, so the inner beat fires at a genuine fold entry.
- One section per run reads partially lit (`candidates` 0.53, `blog` 0.86 /
  0.62) — varies run to run, so timing-dependent.
- The "OUR THREE OPERATING PILLARS" block has a large dead vertical gap
  between the heading and the cards, and the three cards sit in a 2+1 grid that
  reads as unbalanced. Layout, not animation.
- Fast scrolling still outruns the 0.4s reveal. Inherent to scroll-reveal;
  fixable only by shortening/removing the animation.

### 3.3 Images

## 4. Verification tooling

Chromium + puppeteer-core are installed. Scripts live in the session scratchpad
(copy them somewhere permanent if you want to keep them):

- `inview.js <base>` — is each section fully lit while it occupies mid-screen?
- `snapback.js <base>` — does any section go lit -> dim -> re-animate?
- `verify.js <base> map` — counts stranded wrappers on `/`, `/about`, `/services`
- `ancestors.js` — walks the ancestor chain of a hidden element reporting the
  CSS property responsible

Launch args that matter: `--host-resolver-rules=MAP uat.phitopolis.io 127.0.0.1`
(DNS points at a public IP the box cannot reach) and `--ignore-certificate-errors`.
Drive scrolling with `page.mouse.wheel()`, **not** `window.scrollTo` — Lenis
ignores programmatic scroll and you will measure a false failure.

## 7. Working from another machine — read this

The two branches are **not** interchangeable:

- **`main`** — app code only. Has all four fixes. Has **no** `Dockerfile`, no
  `deploy/`, no CI. Cannot be deployed on its own.
- **`uat-staging`** — everything in `main` plus the deploy stack, the security
  headers, the extra tests, and the lint pass `0fa7f78`, **which exists on this
  branch only**.

Sync is manual, and forgetting it is what caused this whole incident:
```bash
git -C <staging> branch -f main-ref <main-commit>
git -C <staging> merge main-ref
```
Merge, never rebase or reset — `uat-staging` carries commits `main` must not lose.
